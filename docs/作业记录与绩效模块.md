# 作业记录与绩效模块（第三方劳务 · 独立运行 / 融入仓储系统）

## 1. 竞品调研结论

| 产品 | 定位 | 可借鉴点 | 本系统的取舍 |
|---|---|---|---|
| **马帮** ERP/WMS | 跨境电商卖家 ERP + 自营仓 WMS | 配货/复核/包装等环节按操作员扫码留痕，可据此统计人效 | 数据在 WMS 里，**劳务公司拿不到也管不了**：本系统接收其导出/推送，按操作员账号映射到自己的员工 |
| **领星** ERP / 海外仓 WMS | 亚马逊卖家 ERP，海外仓入库/出库/FBA 中转 | 作业单据（入库单、出库单、货件）与操作账号绑定 | 同上；预设领星常见列名（操作账号、出库单号、货件单号…） |
| **易仓** WMS/OMS | 海外仓 / 第三方仓储系统，开放 API | 任务级作业记录、客户代码维度 | 同上；支持 API 推送，以作业单号幂等 |
| **Beekeeper** | 一线员工沟通 App（频道、班次通知、多语言自动翻译、问卷、必读确认） | 一线员工手机端、多语言、班次信息触达 | 工人端报工页面直接放在「打卡」页，中德双语标签；本系统已有 8 语言界面和消息模块 |
| **clockin** | 德国移动端工时记录（一键开始/结束、项目/工序时间、GPS、照片、DATEV 导出、客户 Leistungsnachweis） | 按「工序/项目」记时、给客户出工时证明 | 作业记录带工时、单号/项目号；按客户导出 CSV 作为 Leistungsnachweis |
| **Eurotime / edtime 类终端考勤** | 德国考勤终端 + 排班（Zeitkonto、ArbZG/MiLoG 合规提醒、工牌） | 工牌/终端打卡、合规 | 本系统已有打卡、Zeitkonto、ArbZG；新增「扫码工位」接口（工牌 + 作业条码 + 数量） |

**关键结论**：WMS（马帮/领星/易仓）记录的是「货」，考勤软件（clockin/Eurotime）记录的是「时间」，Beekeeper 解决「沟通」——
但**没有一个产品把「某个劳务供应商的某个工人，在某客户（Amazon/TEMU）某仓库做某作业，产出多少、用时多少、质量如何、该结算多少」串起来**。
这恰好是第三方劳务公司（Personaldienstleister，承接 Amazon/TEMU 仓内作业、装卸柜、项目）的核心管理对象。

> 说明：马帮/领星/易仓 各账号的导出模板可自定义，系统内置的列名预设基于常见字段整理，首次接入请用「预览」核对，必要时配置字段映射。

## 2. 设计：两种运行模式

```
          独立模式（无仓储系统）                       集成模式（客户使用 WMS）
  ┌─────────────────────────────────┐      ┌───────────────────────────────────────┐
  │ 班组长批量录入（纸质工时单数字化）│      │ 马帮/领星/易仓 导出 Excel → 文件导入   │
  │ 工人手机报工（打卡页）            │      │ WMS/中间件 → POST /api/v1/ops/ingest   │
  │ 扫码工位（工牌+作业条码+数量）    │      │ 卸柜记录同步（本系统已有模块）          │
  └───────────────┬─────────────────┘      └───────────────────┬───────────────────┘
                  └─────────────► 作业记录 OperationLog ◄────────┘
                                        │  员工匹配：工号 → 操作员账号映射 → 账号=工号 → 姓名
                                        │  作业匹配：代码 → 名称 → 关键词（拣货/配货/pick…）
                                        │  未识别 → status=unmatched，补映射后一键重新匹配
                                        ▼
                     绩效引擎（工效标准法）+ 质量事件 + 工时单/打卡兜底工时
                                        ▼
            按 员工 / 劳务供应商 / 作业 / 客户 / 仓库 / 日期 排名 · 计件金额 · 客户结算额 · CSV
```

### 绩效口径
- **标准工时** = Σ 数量 ÷ 作业类型的标准 UPH（每人每小时标准产量）。拣货、打包、卸柜等不同作业因此可以合并比较。
- **实际工时**：优先用作业记录自身的工时；WMS 只推了扫描时间、没有工时时，用当天 **工时单 → 打卡** 的班次工时减去已填工时，按标准工时比例分摊。都没有则该记录只计产量，不计效率（不会虚高）。
- **效率%** = 标准工时 ÷ 实际工时 × 100（100% = 达到标准）。
- **质量分** = 100 − 事件扣分（轻微 5 / 严重 15 / 重大 40，表扬 +5）− 差错率每 1% 扣 10 分。
- **综合分** = 效率分 × 权重 + 质量分 × 权重（默认 70/30，可在看板上调）；效率分 = min(效率%, 125) × 0.8。
- **等级**：A ≥ 90 超出标准 · B ≥ 75 达标 · C ≥ 60 待改进 · D < 60。

### 权限（行级隔离）
| 角色 | 作业记录 | 绩效 |
|---|---|---|
| admin / hr / mgr | 全部，可配置作业类型/映射 | 全部 |
| wh 仓管 | 仅本仓库，可录入/确认 | 仅本仓库 |
| sup 劳务供应商 | 仅本供应商员工（只读） | 仅本供应商员工 |
| fin 财务 | 只读 | 全部 |
| worker 工人 | 仅本人，可自助报工 | 仅本人 |

API Key 接入源仅 admin 可管理；密钥只保存 SHA-256 哈希，创建/轮换时显示一次。

## 3. 使用步骤
1. **作业记录 → 作业类型与工效标准**：按各仓实测调整标准 UPH、计件单价、客户单价（系统已预置收货/上架/拣货/打包/贴标/出库/退货/盘点、Amazon FBA 备货、TEMU 分拣、20/40/45 尺柜及 LKW 装卸、项目计时）。
2. 选择数据来源：
   - 无 WMS：**班组录入**（一组人一次录完）或工人在「打卡」页报工；
   - 有 WMS：**文件导入**（先预览再导入）或 **WMS 接入** 创建 API Key 让对方系统推送；
   - 装卸柜：**WMS 接入 → 卸柜记录同步**。
3. 有「未匹配」记录时，在 **WMS 接入/账号映射** 把 WMS 账号映射到员工（自动重新匹配）。
4. 仓管/HR 在 **作业记录** 勾选确认；在 **质量事件** 登记错拣、破损、投诉、表扬。
5. **绩效看板** 查看排名、导出 CSV（供应商对账 / 客户 Leistungsnachweis / 计件工资）。

## 4. API 速查（`/api/v1/ops`）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST/PUT/DELETE | `/types` | 作业类型 |
| GET | `/logs`、`/logs/export` | 查询 / 导出作业记录 |
| POST | `/logs`、`/logs/batch` | 单条 / 班组批量录入 |
| POST | `/logs/confirm`、`/logs/reject`、`/logs/rematch` | 确认 / 驳回 / 重新匹配 |
| POST | `/report`、GET `/my` | 工人自助报工 / 我的当日与本月绩效 |
| POST | `/station` | 扫码工位（工牌 + 作业条码 + 数量） |
| POST | `/import`（multipart，`dry_run`） | Excel/CSV 导入，`system` = generic / mabang / lingxing / eccang |
| POST | `/ingest`（Header `X-API-Key`，`?dry_run=true`） | 外部系统推送 |
| POST | `/sync/containers` | 卸柜记录 → 作业记录 |
| CRUD | `/sources`、`/aliases`、`/quality` | 接入源 / 账号映射 / 质量事件 |
| GET | `/performance`、`/performance/export` | 绩效（`group_by` = employee/supplier/op_type/client/warehouse/date） |

推送示例：
```bash
curl -X POST https://<域名>/api/v1/ops/ingest \
  -H "X-API-Key: ybk_xxx" -H "Content-Type: application/json" \
  -d '{"records":[{"task_id":"T-1001","operator":"zhang01","op_type":"拣货","qty":120,
       "start_time":"08:00","end_time":"09:00","date":"2026-10-08","client":"Amazon"}]}'
```

## 5. 后续可扩展
- 定时从马帮/领星/易仓开放 API 主动拉取（需各自的 AppKey，目前以推送/导入为主）；
